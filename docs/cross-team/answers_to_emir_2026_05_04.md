## Архитектура и инфра (Winston — Architect)

7. Production DB — PostgreSQL на Railway или SQLite (dev.db)?
   - **Ответ:** **Production = PostgreSQL на Railway** (`postgres.railway.internal`). Локальная разработка:
     - **Docker Compose** Postgres 15-alpine (см. `docker-compose.yml`) — для full-stack local
     - **SQLite** `backend/dev.db` (см. `feedback_local_dev_setup.md`) — для быстрых E2E тестов и unit-тестов без Docker

     Алан использует SQLite на dev-машине. Эмиру удобнее SQLite если нужно быстро запустить, или Docker Compose если нужно точное соответствие prod.

8. Сколько диалогов/день проходит через платформу Ex-Machina (не отдельный Bot-Azure)?
   - **Ответ:** **На Ex-Machina prod — 0 в день** (нет реальных клиентов, только демо-проверки). Для контекста: Ton Azure (на legacy Bot-Azure) — **~7 диалогов/день**, в сезон ожидаем **20+/день**. Когда мигрируем Ton Azure на Ex-Machina и/или Назира приведёт 2 первых клиента — увидим первый реальный traffic. Пока бекенд в режиме «спящий».

9. Redis планируется? Или пока in-memory state хватает?
   - **Ответ:** **Планируется в Sprint 3+**. Сейчас in-memory state используется в:
     - `demo_chat.py` — rate limiter (20 req/IP/10 min)
     - `operator_reply_state` (для будущего двустороннего канала `#26`)
     - `followup_service` — таймеры

     **Триггер для Redis:** когда Railway перейдёт на multi-instance autoscale ИЛИ при миграции на Contabo VPS с несколькими backend контейнерами. Пока 1 instance — работает.

10. CI/CD настроен или деплой через git push → Railway auto-deploy?
    - **Ответ:** **Railway auto-deploy** на push в `main`. Dockerfile запускает `alembic upgrade head && uvicorn …`. Отдельного CI (GitHub Actions) нет. Тесты (57 unit) прогоняются **вручную локально перед коммитом** через `pytest`. Простой GH Actions workflow с pytest + линтером — Sprint 3+ техдолг.

11. Мониторинг/алерты есть? Как узнаёте что бот упал?
    - **Ответ:** Минимум:
      - `notification_service` — TG-нотификации владельцу отеля при критических событиях (`needs_manager`, `payment_details_missing`)
      - Health check скрипт для VPS (упомянут в memory)
      - Railway встроенный uptime monitor (базовый)

      Чего нет: Sentry / Datadog / log aggregation / алерта Алану «бот упал» / latency-метрик / cost-overrun алертов. Это техдолг для Sprint 4+ когда будет 5+ платящих клиентов.

12. Переезд на Contabo VPS — актуален или остаётесь на Railway?
    - **Ответ:** **Актуален, не приоритет.** План: переезд на Contabo VPS ($12/мес) когда Railway-биллинг станет ощутимым (~$30/мес) ИЛИ когда понадобится статичный outbound IP для Shelter integration (есть риск GeoIP блокировки немецких IP — не проверяли).

## Конкуренция и стратегия (Victor — Strategist)

25. Чем Ex-Machina конкретно лучше NURAI для клиента?
    - **Ответ:** **5 структурных преимуществ** (из competitor intel + Lean Canvas Block 9):

      1. **Hotel-специализация vs general-purpose CRM** — у NURAI 60+ клиентов в 9 отраслях, hotel-кейсов 0. У нас всё заточено под hotel: PMS-handoff, fix_prices safeguard, payment_details fail-loud, dialog categorization (booking/general/rooms/service).
      2. **KG-нативно** — у нас встроено через prompting. У NURAI этого нет (даже HotelBot-программисты не знают как реагировать на mix RU+KG, у них handoff на оператора).
      3. **Прозрачная цена $800+$40 vs $79-349 от NURAI без понимания за что** — для small-hotel КР, привыкших к сюрпризам, это killfear.
      4. **Настройка за неделю vs неизвестность у NURAI** — Назира приходит, настраивает за встречу, бот работает.
      5. **Local case (Ton Azure) с реальными метриками** — 58+ диалогов, 49 уникальных клиентов на Иссык-Куле. NURAI hotel-кейсов показать не может.

      Sales asset: `docs/sales/hotelbot_comparison_2026_04.md` (для HotelBot готов, для NURAI — материал есть, оформить — TODO).

      **Контр-возражение** если клиент спрашивает «почему не NURAI?»: «Они отличный general CRM, но если вам нужен бот именно для отеля — Exely интеграция, hotel-специфичные фичи — ищите hotel-vendor. Мы с июня выкатываем Exely auto-close, NURAI этим не занимается».

26. Если PMS (TravelLine/Shelter) добавят AI-бота бесплатно — какой план Б?
    - **Ответ:** **Текущий план — мы интегрируемся с PMS, не конкурируем.**
      - **Shelter / Altegio / Exely** — интеграция планируется в зависимости от того, какая система стоит у клиента
      - Мы **проверили API** этих систем — у всех есть endpoint'ы для **создания брони** и **запроса свободных номеров**, что нужно для бота
      - Прямого партнёрского outreach к Shelter/Altegio пока не было — изучили публичные API. Outreach как партнёрам — Sprint 3+ (после закрытия Sprint 2 anti-churn)
      - **Exely Distribution API** — интеграция запланирована на **июнь 2026** (Lean Canvas v1)

      **План Б если PMS встроит AI бесплатно:**
      1. **Преимущество глубины** — мы точечно лучше (двусторонний канал, ROI report, dialog classifier, KG-mix). PMS-бот будет «бот общего назначения».
      2. **Цена-моат** — $40/мес наш минимум; если PMS включит «AI бесплатно» в свой $80-120/мес, мы остаёмся в нижней нише для тех кто не хочет полный PMS.
      3. **Pivot опция:** превратиться в **add-on** для PMS (специализированные фичи поверх Shelter) — white-label.
      4. **Long-term hedge:** Exely Distribution API — Exely международная channel manager, не зависит от Shelter.

27. Готовы ли вы к сезонному росту (лето) технически и организационно?

      - ✅ Демо-бот, share-links, ROI-калькулятор на лендинге, /cases/ton-azure
      - ✅ Followup, dialog classifier, price validator, payment details fail-loud

      **Технически НЕ готово:**
      - ❌ `#26` двусторонний канал — критично без него
      - ❌ `#17` активация-гайд — критично против churn
      - ❌ Redis (Railway autoscale сломает in-memory)
      - ❌ SSE/WebSocket вместо polling (при 5+ отелях polling 10s × 5 = 5x нагрузки)

      - 🚨 Ротация `OPENROUTER_API_KEY` (висит с 28.04 в git-истории)

      **Организационно готово:**
